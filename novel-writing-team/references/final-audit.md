# Final Continuity + Word-Count Audit

ใช้เอกสารนี้หลัง rewrite pass เสร็จทั้งเรื่อง และก่อน editorial polish pass

## เป้าหมายของ final audit
- ตรวจว่าความต่อเนื่องทั้งเรื่องยังไม่หลุดหลังรีไรต์ครบแล้ว
- ตรวจว่า open loops ถูกจ่ายคืนครบหรือมีจุดค้างตรงไหน
- ตรวจว่า arc ตัวละครหลักและความสัมพันธ์เดินครบจากต้นถึงจบ
- ตรวจว่ากฎโลก วัตถุสำคัญ บาดแผล และราคาของอาคมไม่ขัดกันเอง
- ตรวจ total word target ว่าถึงเป้าหมายหรือยัง
- สรุปว่าต้นฉบับพร้อมเข้าสู่ polished draft หรือยัง

## สิ่งที่ต้องตรวจ

### 1. Story-wide Continuity
- timeline ข้ามทุกตอน
- สถานะตัวละครหลักและรอง
- บาดแผล ร่องรอย และผลค้างจากอาคมหรือเหตุการณ์สำคัญ
- ความสัมพันธ์ที่เปลี่ยนไปตามลำดับตอน
- วัตถุ เบาะแส หรือคำสัญญาที่ต้องจ่ายคืน
- กฎโลกหรือกฎเวทที่เคยตั้งไว้

### 2. Episode-to-Episode Flow
- ตอนเปิดและตอนปิดส่งต่อกันลื่นหรือไม่
- emotional carry-over จากตอนก่อนหน้าถูกเก็บมาหรือหลุดหาย
- ข้อมูลใหม่ในตอนหลังไม่ขัดกับตอนต้น
- climax, aftermath, และ ending arc ลงน้ำหนักเหมาะสม

### 3. Word-Count Audit
- นับจำนวนคำรายตอน
- รวมจำนวนคำทั้งเรื่อง
- เทียบกับ total word target ใน project README และ longform plan
- ระบุชัดว่าเกินเป้า / ต่ำกว่าเป้า / ใกล้เป้า
- ถ้าเครื่องมือแบ่งคำภาษาไทยแบบ exact ไม่มี ให้ใช้วิธีนับแบบประมาณการที่สม่ำเสมอทั้งโปรเจกต์ และระบุวิธีไว้ชัด

### 4. Action Recommendation
- พร้อมไป polish ได้ทันที
- ควร polish พร้อมเก็บงานย่อยบางจุด
- ควรขยายบางตอนก่อน polish
- ควรซ่อม continuity สำคัญก่อนเดินต่อ

## รูปแบบการทำงานที่แนะนำ
1. อ่าน continuity tracker, episode map, longform plan, README และตอนจริงทั้งเรื่อง
2. ตรวจความต่อเนื่องข้ามต้น กลาง ปลายเรื่อง
3. สรุปจุดเสี่ยงระดับ สูง / กลาง / ต่ำ
4. นับจำนวนคำรายตอนและรวมทั้งเรื่อง
5. บันทึกผลใน `manuscript/projects/[project-slug]/final-audit.md`
6. ถ้าผู้ใช้สั่งให้ทำต่อจนจบ ให้เดินต่อเข้า editorial polish pass อัตโนมัติเมื่อปัญหาอยู่แค่ระดับแก้ได้ใน polish
7. ถ้ามีปัญหา continuity ระดับโครงสร้าง ให้หยุดและรายงานก่อน

## Continuous Finish Mode
- ถ้าผู้ใช้สั่ง `ทำต่อจนจบ`, `ทำให้เสร็จทั้ง workflow`, หรือสั่งรีไรต์ทั้งเรื่องพร้อมเจตนาปิดงานต่อ ให้ตีความว่าอนุญาตให้รัน `rewrite -> final audit -> editorial polish` ต่อเนื่องได้
- ไม่ต้องขออนุมัติซ้ำระหว่าง final audit และ polish ถ้าไม่มีปัญหาโครงสร้างใหญ่
- หลัง final audit ให้อัปเดต `README.md` ของโปรเจกต์และ `manuscript/projects/index.md` ด้วยสถานะล่าสุดเมื่อเหมาะสม
